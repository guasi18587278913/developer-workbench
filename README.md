# Developer Workbench

我的个人开发工作台。这里保存我在产品设计、AI 编程和独立开发中反复使用、确认有效的提示词、工具、检查清单和模板。

这不是资料收藏夹。只有真正解决过问题、以后还会继续使用的内容才放进来。

## 收录原则

1. **拿来就能用**：每个条目都写清适用场景、所需输入和使用方式。
2. **解决具体问题**：不收泛泛的方法论，只收能推动开发工作的材料。
3. **先小后大**：需要什么再增加什么，不提前搭建复杂分类。
4. **不存秘密**：API Key、Token、账号、客户数据和内部敏感信息不得提交。

## 当前内容

### 提示词

- [方案压力测试：陌生架构师审查](prompts/solution-stress-test.md)：在进入开发前，让一个没有历史包袱的 AI 找出方案里的隐含假设、过度工程、欠缺工程和高风险边界。

### 设计参考资料

- [个人设计素材库](design-library/README.md)：从 Framesbase 整理的网站、应用界面、页面模块与背景。支持 AI 按区域和风格筛选，再读取预览、提示词或源码。

这里的原始参考尚未逐条验证实现效果，与已验证的工具分开保存。完整数量与缺失项以素材库中的采集清单为准。

### AI 开发 Skill 与模板

- [项目规则与 Skill](skills/project-harness/SKILL.md)：整理任务范围、上下文入口、工具选择和验证约定。
- [规格与验收模板](skills/spec-to-acceptance/SKILL.md)：把需求串成规格、计划、任务与验收，适配已有 Spec Kit。
- [测试样例与评测材料](skills/behavior-and-evals/SKILL.md)：检查代码行为和 AI 输出，保留有效失败与真实验证证据。
- [知识与能力接入方式](skills/knowledge-capability-adapter/SKILL.md)：复用已有检索与业务服务，明确数据和执行边界。
- [开发、发布与故障记录](skills/delivery-handoff/SKILL.md)：生成可接续的交接单和有证据的故障复盘。

每个目录包含 `SKILL.md` 和 `assets/` 模板。将整个目录提供给支持 Agent Skills 的工具，或让 AI 读取入口文件并按当前任务使用；保留目录结构以便读取模板。它们是从实践提炼的新整理版本，目标项目的适配效果仍需按实际任务验证。

按“名称、作用、链接”查看或分享：[AI 开发可复用资源清单](docs/ai-development-resources.md)。

## 后续怎么扩展

后续按实际重复任务增加工具、检查清单或模板。每个新条目至少要回答三个问题：什么时候用、怎么用、什么结果算有效。
