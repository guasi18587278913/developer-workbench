# Developer Workbench 初始设计

## 目标

建立一个长期维护的个人开发工作台，集中保存经过实际使用验证的提示词、工具、检查清单和模板，减少每次开发重新整理方法的成本。

## 首版范围

首版只建立仓库入口和一个提示词条目，不制作网站、不增加搜索、标签系统或自动化发布。等内容数量产生真实管理问题后再扩展。

## 内容约定

- README 负责说明仓库用途、收录标准和内容索引。
- 每个条目独立成文，包含适用场景、使用方法、完整内容和有效性判断。
- 不提前创建空分类；新内容出现时再增加对应目录。
- 仓库不得保存密钥、账号、客户数据或其他敏感信息。

## 首个条目

“方案压力测试：陌生架构师审查”用于在开发前引入一个没有前序讨论包袱的 AI，重点检查隐含假设、过度工程、欠缺工程、边界风险和责任断点，并给出分级结论。

## 验收

- 从 README 可以找到首个条目。
- 提示词可以整段复制到新的 AI 对话中使用。
- 输出要求包含问题证据、失败路径、优先级和明确结论。
- 仓库保持最小结构，没有与当前需求无关的实现。
