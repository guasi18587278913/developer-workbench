## 核心方向

**把“搜客 / 找线索 / 提取名单”这件事做成半自动或全自动产品。**

用户只要给一句话，系统就能像真人一样操作浏览器，到指定平台搜索目标帖子 / 账号 / 关键词，再把可用线索提取出来，整理进表格或 CRM。

---

## 为什么这个方向值得记

- `browser-use` 已经证明：AI 能像真人一样操作网页，不只是爬静态页面
- 搜客是很多行业都存在的刚需，且人工极重、重复、枯燥
- 线索名单一旦更精准，价值就非常直接，不是“看起来厉害”，而是能立刻接业务
- 这类需求既可以做成工具，也可以先做成服务，验证路径比纯 SaaS 更短

---

## 典型使用场景

### 1. 留学 / 移民 / 求职线索
- 去小红书、X、贴吧、知乎等平台搜索：
  - 想去英国留学
  - 想申请港校
  - 想转码找工作
- 把发帖人 ID、发布时间、帖子链接、关键词提取出来

### 2. ToB 销售线索
- 搜行业关键词、岗位关键词、老板账号、公司动态
- 提取潜在客户公司名、联系人、公开表达出来的需求信号

### 3. 本地生活 / 招商 / 加盟
- 搜“想开店”“找加盟”“想找代运营”等表达明确需求的内容
- 做地区化名单整理

### 4. 自己做业务
- 不是只卖工具，也可以先拿它给自己业务导流
- 先把“自动化获客”跑通，再决定要不要产品化

---

## 产品功能设想

| 功能 | 描述 | 优先级 |
|------|------|--------|
| **一句话任务输入** | 用户直接描述要找什么人、在哪个平台找 | P0 |
| **平台任务模板** | 小红书 / X / LinkedIn / 贴吧等预设模板 | P0 |
| **线索提取** | 自动提取账号、链接、关键词、发布时间、备注 | P0 |
| **去重与筛选** | 去掉重复账号，过滤无效帖子 | P0 |
| **线索评分** | 按“需求强弱”给线索打分 | P1 |
| **导出表格 / CRM** | CSV、飞书表格、Notion、HubSpot | P1 |
| **定时任务** | 每天自动跑，持续补新名单 | P2 |
| **合规提示** | 平台风险、隐私提示、频率限制 | P2 |

---

## 先做服务，还是先做产品？

我更建议：**先服务，后产品。**

### 第一阶段：人工盯 + AI 跑
- 先接 1-2 个真实需求
- 比如“帮留学中介找一批高意向客户”
- 手工定义规则，AI 帮跑，最后人工复核

### 第二阶段：半产品化
- 把高频流程固化成模板
- 不同行业只换关键词、平台和导出格式

### 第三阶段：再考虑 SaaS
- 当模板稳定、交付结果稳定，才值得做成真正产品

---

## 变现模式

| 模式 | 描述 |
|------|------|
| **代跑服务** | 按次收费：帮客户搜一批高质量名单 |
| **订阅式线索供给** | 每周 / 每月持续交付新增线索 |
| **定制工具搭建** | 给客户搭一套自己的搜客工作流 |
| **SaaS** | 让客户自助输入需求、自己跑任务 |

---

## 技术方案（初步）

- **浏览器自动化**：browser-use / Playwright
- **任务编排**：Python + LLM agent
- **数据存储**：Supabase / PostgreSQL / 飞书多维表格
- **去重和打分**：规则引擎 + LLM 评估
- **交付层**：CSV / Sheets / 飞书 / CRM API
- **后续增强**：代理池、频控、账号体系、任务日志

---

## 风险和边界

- 平台风控：不是所有平台都适合高频自动化
- 线索质量：搜到“提到关键词的人”不等于“愿意付费的人”
- 合规问题：隐私、导流、账号安全都要小心
- 不能把“自动挖名单”直接等同于“自动成交”

---

## 三步行动清单

- [ ] **先找一个真实行业试跑**：留学 / 求职 / ToB 销售，三选一
- [ ] **定义最小交付**：名单里到底要哪些字段，什么叫“可用线索”
- [ ] **拿一次真实结果**：不先吹产品，先验证能不能找到对业务真有用的名单

---

## 一句话判断

**这不是一个“酷炫自动化 demo”，而是一个很可能直接碰到钱的方向。关键不在技术能不能跑，而在跑出来的名单值不值钱。**
