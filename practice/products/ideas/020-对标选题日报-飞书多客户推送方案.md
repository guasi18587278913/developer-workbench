# 020 对标选题日报 · 飞书多客户推送方案

**状态**：方案设计中（已确认架构、待动手实现）
**创建**：2026-06-03
**灵感来源**：跟瓜哥聊"如何把选题日报给没装 Claude Code 的人用"——bridge 模式行不通，改成"对方建 bot + 你这边主动推"的单向架构

---

## 核心架构（最关键的设计判断）

让对方装 lark-channel-bridge ≠ 让对方"无门槛使用"——bridge 本质是飞书→本地 Claude Code 的桥，对方要跑 bridge 就要装 CC + lark-cli + skill + TikHub key，反而成了重门槛。

**改成单向推送**：

- **对方端**：在自己公司飞书管理后台创建一个"自建应用"（10 分钟），拿到 `app_id` + `app_secret`，给瓜哥
- **瓜哥这边**：用对方提供的 token 调飞书 OpenAPI 主动推消息，对方在自己飞书里收
- **对方零配置**：不装 CC、不装 lark-cli、不装 skill、不需要 TikHub key

---

## 架构对比

| | 让对方装 bridge | 给瓜哥 token、瓜哥主动推 |
|---|---|---|
| 对方要装 | CC + lark-cli + skill + Python 全套 | 啥也不装 |
| 对方要会的事 | OAuth 授权、本地命令、排错 | 飞书后台点几下创建 app |
| TikHub 成本谁担 | 对方 | 瓜哥（用户付订阅费 cover） |
| 加新用户的成本 | 对方重装一遍 | 对方填个 token 给瓜哥 |
| 对方端排错 | 对方自己调试 | 找瓜哥 |
| 商业模式可行性 | 不行 | 可行 |

## 实现步骤（按优先级）

### 1. skill 改造：支持多客户配置

把 `config.json` 拆成 `clients/<userid>/config.json`，每个客户独立的：
- 对标账号清单（accounts）
- 内容方向（direction）
- 倍数门槛（multiplier、floor）
- 飞书推送目标（chat_id 或 user_id）

`run_daily.py` 接 `--config <path>` 参数，按指定 config 跑。

### 2. AI 自动判定相关性（去掉人工那一步）

当前每条爆款相不相关是瓜哥在 Claude Code 里手动判的——多客户必须自动判，否则一个人服务不了几个客户。

实现：每个客户 config 里的 `direction` 字段喂给 Claude API，让它给每条爆款打"相关/不相关"标签 + 一句话理由。这步是把 skill 流程里的"第 2 步判定"从人工搬到 API。

### 3. lark-cli 多 app 配置 + 推送

lark-cli 原生支持多 app 配置——给每个客户存一份 token，循环调 `lark-cli im +messages-send` 发到对方飞书。文件结构：

```
clients/
  client_a/
    config.json
    lark-app.json   ← {app_id, app_secret}
  client_b/
    config.json
    lark-app.json
```

### 4. crontab 定时跑全部客户

每天早上 7 点 cron 触发：

```bash
for client in clients/*/; do
  python3 ~/.claude-account2/skills/对标选题日报/scripts/run_daily.py --config "$client/config.json"
  python3 ~/.claude-account2/skills/对标选题日报/scripts/get_links.py ...
  python3 ~/.claude-account2/skills/对标选题日报/scripts/auto_judge.py --direction "$client/direction.txt"
  lark-cli im +messages-send --app-config "$client/lark-app.json" --user-id $(jq -r .push_target "$client/config.json") --markdown @daily_report.md
done
```

- **试用**：第一周免费，跑 2-3 期日报让客户感受到价值
- **订阅价**：999-2999/月（精准营销内容、给 MCN/品牌/代运营公司）

## 关键风险/待验证

- [ ] **飞书自建 app 跨企业可达性**：对方的"自建应用"瓜哥这边用 token 推消息，对方公司的安全策略会不会拦？需要 1-2 个种子客户试
- [ ] **AI 自动判定的准确率**：人工判定是日报"灵魂"，AI 替代后会不会出现"看似相关其实没用"的误判？需跑 1-2 周看客户反馈
- [ ] **TikHub 成本压力**：10 客户 × 50 号 × 每天 = 1500-2000 call/天，TikHub 套餐能不能撑住？正在调研更便宜的 API 替代方案
- [ ] **客户端"看不看"**：日报推过去对方会不会真打开？开 read receipt 看打开率，2 周内没打开就是钩子不对

## 第一步要干的事（本周）

1. 找 2-3 个种子客户（深海圈里做 AI 自媒体或 MCN 朋友）
2. 帮他们走一遍"飞书后台创建自建 app"流程，拿到 token
3. 给每个客户建 config（对标账号 + 方向）
4. 手动跑 1 周（不要急着自动化），每天早上跑完手动推
5. 1 周后收反馈：他们看不看？拍不拍？愿意付多少钱？

**先不要做的事**：crontab 自动化、Web 前端、计费系统。MVP 阶段一切动作越手动越好——手动跑能直接听到客户哪一条选题最值钱，自动化太早会盲飞。

## 数据 API 成本调研结论（2026-06-03 完成）

### 一句话结论

**TikHub 在当前量级不贵，月费 $1.5 不到，省钱方向不是换平台，是减少无效调用。**

按"48 账号 × 每天 1 次 = 50 call/天"测算，TikHub 单价 $0.001/call → 月费 **$1.5（≈¥11）**。10 客户 × 50 账号扫到 500 call/天，进 30% 折扣档 = **$10.5/月（≈¥75）**。50 客户 = $37.5/月。真正贵起来要到 200+ 客户、月调用 200 万+。

### 立刻能做的 skill 优化（不换平台）

把对标日报改成「先增量、再全量」：每天先用 `last_cursor` 拉每个账号最近 5 条，**全部是 7 天内的新笔记**才继续翻页。多数博主每天发 0-1 篇，第二页就退出。**单账号请求数从平均 30 条降到 12 条，调用量直接砍 60%**。这一招在 TikHub 上立刻生效，不用换平台。

### 备选方案：Apify actorzlab/rednote-scraper

- 价格 **$3/1k**（比 TikHub 便宜 30-60%）
- 仅成功扣费，actor 自带住宅代理
- 5 种模式：keyword search / note 详情 / user profile / topic feed / trending
- 字段齐：title、likes、collects、comments、hashtags、images、video、time
- 限制：userPosts 模式要传完整 profile URL（不是纯 user_id，要先拼一下）
- **缺点：只做小红书一家**，actorzlab 这位作者旗下没有 Douyin/TikTok/Instagram 等其他平台

### Apify 生态扩展性（未来扩平台用）

actorzlab 只做小红书，但 **Apify 平台本身是个通用爬虫市场**——同一份 Apify 账号、同一份余额能跨作者买多个 actor，覆盖：

- Douyin / 抖音：apibox、natanielsantos 等
- TikTok：Apify 官方有
- Instagram、YouTube：官方 actor + 第三方
- Twitter/X：apify 官方

**如果未来想从小红书扩到 Douyin/抖音/B 站，走 Apify 一家比挨家挨户接 API 省事**。

### 不建议的方向

- **国内 SaaS（千瓜/新红/灰豚/飞瓜）**：1599-8599/月，但**只给网页看板、不给 API**，接不进自己 SaaS，直接排除
- **开源自建（MediaCrawler / xhs / Spider_XHS）**：技术上能跑，但小红书 2026 风控是「cookie 10 分钟过期 + x-s 签名季度更新 + 设备指纹 + 滑块」五重防线。**100 客户以下不要碰自建**，省下来的钱不够付工程师时间

### 行动建议（按优先级）

1. **本周**：跑 skill 增量优化（砍 60% 调用量），不换平台
2. **找种子客户阶段**：继续 TikHub
3. **跑到 5-10 客户**：花 $5 跑一次 Apify actorzlab 实测对比字段完整度（重点验 `desc` 正文、`collected` 收藏），数据齐就切
4. **100+ 客户再考虑**：自建 + 住宅代理
