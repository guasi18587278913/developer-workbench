# 008-AI叙事剪辑助手

**来源**：小红书评论区痛点（"口播剪辑红海，叙事剪辑蓝海" + "20G素材自动匹配文案"）

## 核心痛点
旅行/叙事博主每次拍摄产生大量素材（20G+），但**"找素材+排顺序"**极其耗时。
- **现状**：AI 生成素材（豆包/即梦）功能被砍，创作者更依赖自有素材。
- **红海**：口播 A-Roll 自动剪辑（剪映、CapCut 都在做）。
- **蓝海**：叙事类剪辑（Vlog、故事片），AI 目前很难根据情绪挑素材、编节奏。

## 产品逻辑（视频版 RAG）
1. **AI 读素材（建立索引）**：本地运行 CLIP 模型，给用户的视频/图片打语义标签（物体+情绪，如"夕阳"、"忧伤"）。
2. **AI 读脚本（Query 理解）**：LLM 把文案拆解为分镜描述（"那天的风很温柔" -> "树叶、长发、慢动作"）。
3. **匹配（Vector Search）**：本地向量搜索，将分镜描述与素材库进行语义匹配。
4. **交付（决策而非渲染）**：生成 `.fcpxml` (Final Cut) 或 `draft_content.json` (剪映) 工程文件。
   - **不生成视频**：避免渲染慢、画质损耗。
   - **用户体验**：打开剪辑软件，时间线上已经铺好了匹配的素材，只需微调。

## 目标用户
- 旅行博主、Vlogger、纪录片创作者。
- **付费意愿强**：时间直接等于金钱。

## 商业模式
- 订阅制：$29/mo
- 买断制：$99 (终身)

## 技术实现 (MVP)
- **形态**：Python 桌面工具（Electron/Tauri 壳）。
- **流程**：拖入素材文件夹 -> 等待索引 -> 粘贴文案 -> 导出工程文件。
- **核心栈**：CLIP + ChromaDB + OpenTimelineIO。
